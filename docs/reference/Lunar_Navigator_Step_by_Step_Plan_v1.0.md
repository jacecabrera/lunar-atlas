### 04 — 提前检查候选数据是否足够

- 负责人：C；类型：研究与数据检查；依赖：02、03。
- 对 12 个历史参照点建立覆盖表：坐标框架、数值 DEM、栅格间距、垂直误差、配准误差、局部危险资料、遗留硬件位置。

- 验收：每个点的缺数据、数据不够精细、已知不满足三种原因分得清楚。

## 9. 作者 API 说明的采纳与纠正记录

来源：用户提供的 Pasted markdown.md。代码证据为本记录固定提交中的公共接口与实现，不代表作者或用户本地后续分支已完成同样修改。以下用于实现对照，不改动原始两份需求资料。

| 编号 | 作者提供的信息 | 采纳方式与需要注意的边界 | 对应步骤 |
| --- | --- | --- | --- |
| API-01 | 统一从 src/sim 导入 | 保留计算层公共入口；逐一确认真实导出、签名与调用者，按文件层级使用正确导入路径 | 02、03 |
| API-02 | sceneState 提供月球位置、地月姿态、太阳方向 | 复用已存在的场景计算；矩阵为 row-major，场景 1 单位为 1000 km；视觉姿态精度仍按步骤 06 核验 | 03、06、17 |
| API-03 | loadTerrain 后使用 siteAt | 采纳前置依赖；统一加载、缓存、错误和并发请求管理。接口存在不代表主页面已接入 | 07、15 |
| API-04 | 手动创建 Site 可不带 horizon | 这是平滑球面模型的构造方式，可用于明确标注的验证或预览，不可用来绕过地形资格检查 | 07–09、13 |
| API-05 | terrainAt 提供高程、区域坡度、基线与分辨率 | 复用数据字段和来源展示；区域坡度不能当足迹最大坡度；换成 LDEM_16 也不能自动满足障碍尺度要求 | 04、07、08、22 |
| API-06 | horizonProfileAt 返回 360 个数 | 仅默认 1° 采样如此；选项改变时核对长度、角度映射和重建插值。mastM、范围及采样选项属于模型参数，不是已测设备事实 | 03、07、24 |
| API-07 | skyAt.sunUp 与 earthUp 均为任意圆盘部分可见 | 作为当前行为记录；按 v0.7 修正地球中心规则。不能照文档原样把两者通用于通信 | 02、09 |
| API-08 | nextEvent/statusAt 返回下一次 rise 或 set | 保留通用事件能力，区分 UI 所需“下一次落下”；无事件保留 null。低层事件示例没有自动携带 Site.horizon | 10、22 |
| API-09 | windows、summarize、intersect 与 compareSites | 优先复用窗口与统计，不重复实现；验证窗口边界和地形传播 | 10、22 |
| API-10 | compareSites.operational | 字段仅表示太阳与地球同时可见；界面应按真实含义命名，不解释成能源合格、任务运行或实际通信成功 | 03、13、22 |
| API-11 | assessViability、simulatePower 及其结果字段 | 可复用时序与结果结构；仍需替换二元发电及旧参数。viable 只表示能源层结果，且低层函数的校验责任需补清楚 | 11–13 |

| API-15 | latLonToVec3、horizonFromProfile、flatHorizon、时间常量 | 复用正确的辅助函数；注意局部/世界坐标、地平线样本定义及单位。月面拾取所需逆转换必须核对导出与转换链 | 03、10、17、19、20 |
